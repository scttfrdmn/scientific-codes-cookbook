# OpenSlide — a CAMELYON16 slide against the publisher's own annotations, on Graviton

Reads a 61440 × 53760 whole-slide image on Graviton4 and reproduces the tumour mask its publisher derived from the annotation polygons. For anyone doing digital pathology on ARM.

## Run it

```bash
make stage RECIPE=pathology    # once: the checks and the publisher's two manifests
spawn task run --spec "$(make -s spec RECIPE=pathology)" --wait
make ls RECIPE=pathology

slide = openslide.OpenSlide("tumor_091.tif")
slide.level_dimensions                                 # 8 levels, 61440x53760 down to 480x420
tile = slide.read_region((4096, 4096), 2, (512, 512))  # RGBA, from the level-2 pyramid
mask = openslide.OpenSlide("tumor_091_mask.tif")       # same dimensions; labels {0, 1, 2}
```

## Make it yours

| In the recipe | Swap for | What to know |
|---|---|---|
| `tumor_091` | any of 399 slides | all on RODA with a publisher md5. **Check the publisher's non-exhaustively-annotated list first** — 20 slides have tumour that is deliberately unannotated, so a mask-vs-annotation check on those is measuring the gap, not the tool. |
| reading from RODA | your own bucket | CAMELYON16 is in **us-west-2** and so is the task, so the 546 MB slide is read in place — 6 s, no copy, no egress. Staging a second copy would be a second thing to keep true. |
| `LEVEL = 4` | 3 for finer, 5 for cheaper | 3840 × 3360 holds the whole mask in ~13 MB. The published size thresholds are in **mm**, so the level changes measurement resolution, not the thresholds. |
| the polygon comparison | your own masks | **the part worth copying.** It reproduces a derived artifact from its own source, and the `Exclusion` group is a free negative control. |
| the slide class | — | **do not assert it.** Measured across nine slides: it is clinical metadata the mask does not determine. See below. |

**Leave the fixture.** `tumor_091` is the smallest tumour slide (546 MB of 399) and carries the geometry that makes the negative control work — an `Exclusion` polygon sitting *inside* a `Tumor` polygon. **Scale it** by looping the same checks over more slides; the analysis is 8 s, so the slide download dominates.

## Shape, size, cost

One task on `m8g.large` (2 vCPU / 8 GiB), TTL 40m as a **backstop** with `cost_limit` $0.15 as the real guard. The **analysis is 8 s**; the 67 s wrapper window is 36 s installing Docker, 17 s pulling the image and 6 s staging 546 MB. Peak RSS 628 MiB, tmpfs high-water 530 MiB of 3882 — so **these timings are not compute cost** ([layout](../../patterns/layout-and-effective-cost.md)).

### The mask is a derived artifact, so it can be reproduced from its source

The publisher's README states the tumour regions were *"generated by converting the annotation
polygons to pixel masks"*. That makes the mask checkable rather than merely loadable: rasterise
the `Tumor` polygons, subtract `Exclusion`, and compare against `mask == 2`.

Dice comes out at **0.999992**, but Dice is reported and not asserted — a floor on it would be a
number picked to pass. The assertion is the claim actually meant: **interiors agree exactly.**
Eroding both sides by 2 px at level 4 (7.2 µm) removes the only legitimate source of
disagreement, which is rasterisation edge convention, and then **all 176,339 interior pixels
agree in both directions** — nothing inside the polygons is unlabelled, nothing outside them is
labelled.

**The `Exclusion` group is what stops that passing vacuously.** A rasterisation that ignored
`Exclusion` would still satisfy the inside→tumour direction. On this slide the Exclusion polygon
(x 47206–47808) lies *inside* Tumor annotation 3 (x 45194–48916), so its interior is inside a
tumour annotation and must still not be labelled tumour. **962 pixels, 0 labelled.** Agreement is
worth nothing unless disagreement was possible.

### A read-overlap invariance needs no reference at all

Reading a region at a pyramid level means stitching tiles. Two reads offset so their regions
overlap must return **identical bytes** in the overlap:

```text
read_region((4096, 4096), level 2, 512x512)  and  read_region((4096+1024, 4096), ...)
  -> 256x512 overlap, max |difference| = 0
```

A stitcher that mishandles tile edges fails this while still producing a plausible-looking image.
Exact, free, and no ground truth required.

### The check that was deleted, and the nine slides that deleted it

An earlier version asserted that the slide's `macro`/`micro` class in `reference.csv` is
reproducible from the mask. **It is not, and the recipe says so instead of asserting it.**

Getting there took two corrections. First, the organizers' own `evaluation/evaluate.py` has a
`compute_evaluation_mask()` whose docstring lists four steps, and a first attempt implemented
three — omitting the dilation that merges fragments of one metastasis. Its real procedure is a
Euclidean distance transform thresholded at `dilation_distance / (spacing * 2.0)` with
`dilation_distance = 75 µm` ("approximately 5 tumor cells"), then `binary_fill_holes`, then
`label(connectivity=2)`, and the size thresholds have the dilation **added back** —
`(200.0 + dilation_distance)`. Implementing it properly merged 8 lesions into 4 and moved the
measurement from 1.3951 to 1.4077 mm, against a threshold of 2.075 mm. Still `micro`.

One slide disagreeing proves nothing, so the same procedure was run over 4 macro + 4 micro slides:

```text
slide       ref     implied   major_mm   feret_mm   exhaustively annotated
tumor_009   macro   macro       8.0440     8.1072   yes
tumor_011   macro   macro       3.7345     3.8043   yes
tumor_004   macro   micro       1.9679     2.1555   yes
tumor_010   macro   micro       0.3811     0.3606   NO
tumor_091   macro   micro       1.4077     1.4694   yes
tumor_001/002/003/005  micro -> micro, 4 of 4, 0.6495 .. 1.3728
```

**The failure is one-sided: no micro slide ever measures as macro, but macro slides can measure
as micro.** Two of the three misses are explicable — `tumor_010` is on the publisher's own
non-exhaustively-annotated list, and `tumor_004`'s Feret diameter (2.1555 mm) clears the
threshold its major axis misses. `tumor_091` is not: 1.47 mm by either metric, fully annotated.

One-sidedness is the informative part. The class is the pathologists' measurement of the original
specimen; the mask is a derived annotation that can under-represent extent. So asserting the class
from the mask compares a clinical label against a geometric proxy for it — a
[method difference, not a correctness check](../../practices/cross-checks.md).

A second assertion went the same way for a different reason: "largest lesion exceeds the 0.2 mm
ITC threshold" was **vacuous**, because `reference.csv` contains no `itc` slides at all (239
negative, 80 micro, 80 macro). Nothing in the dataset could have failed it, so it was removed
rather than kept as decoration.

|---|---|
| slide / mask / annotations | RODA `s3://camelyon-dataset/CAMELYON16/`, **read in place in us-west-2** — 546,437,217 + 8,357,394 + 85,520 B |

| the manifests themselves | `checksums.md5` and `reference.csv` pinned by sha256 at staging — every reference is read out of them, so a re-published manifest must not silently redefine the answer |
| checks | `identities.py`, pinned by sha256 |
| image | `quay.io/aarchsci/pathology@sha256:b3fb3cdd…` — openslide 4.0.1, openslide-python 1.4.6, scikit-image 0.26.0, scipy 1.18.1, python 3.14.8 |

Tier 1: the publisher issues its own checksums, so nothing here needs a hash we invented. Staging
additionally refuses to continue unless all three objects have a `checksums.md5` line, the slide
is still classed `tumor,macro`, and each object is the expected byte count — so a silent
re-publish fails before an instance is paid for.

cosign-verified against `playgroundlogic/aarchsci`; the signature covers the **manifest-list**
digest, so verify the tag and pin the arm64 digest (the list also carries an `unknown/unknown`
attestation entry, which is not an image).

### Run + verify

```sh
make stage RECIPE=pathology
spawn task run --spec "$(make -s spec RECIPE=pathology)" --wait
aws s3 cp "s3://$(make -s print-bucket)/runs/pathology/r1/score.tsv" -
```

Fails on a pin mismatch, an md5 that disagrees with the publisher, a WSI and mask that are not
pixel-aligned, a pyramid that is not exact powers of two, a read overlap that is not byte-equal, a
mask value outside `{0,1,2}`, a single polygon-interior pixel disagreeing either way, or any pixel
inside `Exclusion` labelled tumour — but check the bucket regardless
([exit 0 isn't proof](../../practices/container-path.md)).

`probe.py` is the one-off that measured the geometry and sizing quoted above — dimensions, level
downsamples, mpp, mask value histogram, peak RSS and the tmpfs high-water mark. It asserts nothing
and is kept only so those numbers can be re-derived rather than trusted; the levels and `mpp` the
checks depend on had to be measured before anything could be written against them
([size from a run, not a guess](../../patterns/sizing.md)).

### Not covered

**The challenge's actual FROC metric**, which is what `evaluate.py` exists to compute — it needs
detections from a trained model, so nothing here speaks to detection performance. **The 20
non-exhaustively annotated slides**, where a mask-vs-annotation check measures the annotation gap.
`CAMELYON17`, which is in the same bucket and has a different labelling scheme.

Also: `tifffile`, `imagecodecs`, `zarr` and `dask` are in this env and unexercised — tiled
out-of-core access over a WSI is a real workload this recipe does not attempt; stain
normalisation; tissue/background segmentation (the bucket ships a `background_tissue/` directory
this recipe ignores); patch extraction pipelines, which are what most pathology users actually
run; and multi-slide throughput, since this is one slide on one box.
