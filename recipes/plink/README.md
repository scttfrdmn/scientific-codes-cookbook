# PLINK — allele counts that add up, and a planted association it has to find

PLINK 1.9 computes allele frequencies and runs a quantitative association scan on Graviton4, checked against integer arithmetic and against a variant whose effect was planted. The catalog's first statistical-genomics recipe, for anyone doing GWAS-style work.

> **What this covers.** 300 samples × 1000 SNPs with 2% missingness, generated by `--dummy` from a fixed seed. Association on a quantitative phenotype. Not population structure, LD pruning, imputation, or a real cohort.

## Run it

```bash
spawn task run --spec "$(make -s spec RECIPE=plink)" --wait
plink --dummy 300 1000 0.02 0 acgt --seed 42 --make-bed --out data   # synthetic cohort
plink --bfile data --freq counts --out pcount                         # integer allele counts
plink --bfile data --pheno pheno.txt --assoc --allow-no-sex --out as  # quantitative scan
```

One task: PLINK builds the cohort, counts alleles, then scans a phenotype that was constructed from one SNP's genotypes.

## Make it yours

| In the recipe | Swap for | What to know |
|---|---|---|
| `--dummy` cohort, seed 42 | your `.bed/.bim/.fam` | everything below works the same on real data — you just lose the planted variant that makes the second check assertable. |
| phenotype built from `snp500` | your own `--pheno` | the phenotype here is *derived from* a genotype on purpose, so the scan has a known right answer. |
| `--assoc` (quantitative) | `--logistic`, `--linear`, `--glm` with covariates | `--assoc` takes no covariates; a real study almost always needs `--linear`/`--glm` plus PCs. |

**Leave the fixture:** 1000 SNPs is enough for the allele-count identity to be a real check (1000 independent comparisons) and for the planted signal to stand ~258 orders of magnitude clear of the runner-up. **Scale it** to your cohort — and expect the runtime to be dominated by I/O rather than the scan, which is why this is a `c8g.large`.

## Shape, size, cost

One task, `c8g.large` (2 vCPU / 4 GiB — PLINK is I/O-bound here, not compute-bound), TTL 12m, cap $0.05. Recorded window **48 s** including cohort generation. **These timings are not compute cost.**

### Check 1 — an exact identity, because the numbers are integers

| observable | assertion | observed |
|---|---|---|
| allele counts | PLINK's `--freq counts` A1 count == an independent hand count from the additive matrix, **every SNP** | **0 mismatches of 1000** |
| planted association | the causal SNP ranks **first** by p-value | `snp500`, p = 7.6e-262 (runner-up 1.9e-4) |
| arm64 from inside | `plink` ELF `e_machine` == 183 | 183 (AArch64) |

The first check is worth the detail. `--recode A` writes the additive matrix, so summing a column gives the A1 allele count directly; PLINK's own count comes from `--freq counts`. Both are **integers**, so the comparison needs no tolerance at all — it either matches exactly or PLINK's counting is wrong.

Getting that required one deliberate choice: **`--freq` prints MAF to only four significant figures** (0.4589 where the true value is 0.458904), which would have forced an arbitrary `1e-4` band. `--freq counts` returns the underlying integers instead and converts a band into an identity. Preferring the exact form over the convenient one is the same move as [asserting the claim you mean](../../practices/cross-checks.md).

The second check is constructed truth, the [photutils](../photutils/README.md) shape: because the phenotype is built from `snp500`'s dosages, the right answer is known before PLINK runs. The margin over the runner-up is ~258 orders of magnitude, so "rank 1" is nowhere near a borderline call.

### The SIGPIPE trap, recorded because it cost a run

`plink --version | head -1` **fails the whole task under `set -euo pipefail`** with exit 141: `head` closes the pipe, PLINK takes SIGPIPE, and `pipefail` promotes that to a pipeline failure. Same shape as a `| awk '…{exit}'` early-exit. The fix is to stop piping into `head`: redirect to a file and read it with `awk 'NR==1'`. Every rank lookup here writes `ranked.txt` first for that reason.

Also: spawn's task shell does not inherit the image's `PATH`, so `/opt/conda/bin` must be exported before `plink` is callable.

### Run + verify
